test: stop ambient WIZARD_BIND from deciding the loopback-default assertions

TestListenAddress and TestMainFunctionStructure assert that listenAddress()
returns the loopback default 127.0.0.1:8099. Both read the ambient environment
first, so a caller that exports WIZARD_BIND (the documented dev-run override
used by verification recipes that boot the wizard on another port) replaced
"default" with the caller's bind and failed the suite:

  handlers_test.go:154: listenAddress() = "127.0.0.1:8000", want "127.0.0.1:8099"
  security_hardening_test.go:380: listenAddress() default = "127.0.0.1:8000", want 127.0.0.1:8099

Pin WIZARD_BIND to unset at the top of each test (Setenv("") unsets) so the
assertion is about listenAddress() rather than about whatever the caller
exported. Two lines of setup per test, additive only.

The tests keep their teeth: with defaultListenAddr flipped to 127.0.0.1:8000
as a negative control, TestListenAddress still fails, and the WIZARD_BIND
override/unset assertions below are untouched. No production behaviour changes
— main.go is not touched, the shipped bind stays 127.0.0.1:8099.

Verified:
